# Releasing model weights

**A weights release is a library release.** One version number covers the
wheel, the weights and the provenance together — there is no separate weights
version, and the package version comes from the git tag via hatch-vcs.

The trainer produces; this package ships. The handshake below is the whole of
it.

## The sequence

1. **The trainer publishes to the Hub.** `uv run scripts/upload_model.py
   --version-tag vN --wordlist <list>` in `tetrak-hy-trainer` uploads the
   bundle, the word list, provenance and the model card to
   `tetrak/easyocr-armenian` and tags the upload. The uploader creates a
   repository private only when it does not exist yet (`--make-public` then
   publishes it after review). `tetrak/easyocr-armenian` already exists and
   is **public, so an upload to it is live at once**: to review first, upload
   to a private staging repository with `--repo-id`, then to the real one.
   See that repo's `tetrak-hy-training` skill.

2. **Resolve the tag to its commit.** The pin must be an **immutable commit
   SHA**, never a branch or tag:

   ```bash
   # the 40-char revision behind the tag
   uv run --with huggingface_hub python -c "from huggingface_hub import HfApi; \
     print({t.name: t.target_commit for t in HfApi().list_repo_refs('tetrak/easyocr-armenian').tags}['vN'])"
   ```

   A tag can be moved. If it were pinned, someone else's push would turn this
   package's checksum check into an outage for every user.

3. **Update the pins — each URL with its checksum, all at the same commit.**
   In `src/tetrak_hy/__init__.py`:

   ```python
   WEIGHTS_VERSION = "vN"
   WEIGHTS_URL = (
       "https://huggingface.co/tetrak/easyocr-armenian/resolve/"
       "<40-char-commit-sha>/tetrak_hy.pth"
   )
   WEIGHTS_SHA256 = "<sha256 of the .pth>"
   WORDLIST_URL = (
       "https://huggingface.co/tetrak/easyocr-armenian/resolve/"
       "<the same commit>/wordlist.tsv.gz"
   )
   WORDLIST_SHA256 = "<sha256 of the word list>"
   ```

   **A URL without its checksum must never ship.** Both-or-neither is enforced
   for the weights in `tests/test_package.py` and for the word list in
   `tests/test_wordlist.py`. Verify each digest against the file you are
   pinning, not against the release notes or the provenance:

   ```bash
   curl -sL "<each URL you just wrote>" | shasum -a 256
   ```

   A release whose word list has not changed still re-pins it: pass the same
   list to the upload with `--wordlist`, so the new Hub commit carries it, and
   point `WORDLIST_URL` at that commit like the weights.

4. **Take the yaml from the same bundle.** `src/tetrak_hy/tetrak_hy.yaml` is
   *generated by the trainer* and arrives with the weights — never hand-edit
   it here. It moves as a pair with the `.pth`: `len(character_list) + 1` is
   the model's `num_class`, so a 170-class head cannot be read under a
   168-class yaml. A charset change is a new model version, never a patch.

5. **Choose the commit type deliberately** — it decides the version:

   | Change | Type | Bump |
   |---|---|---|
   | New weights, same charset (a fine-tune) | `feat:` | minor |
   | New weights with a widened charset | `feat:` | minor |
   | Correcting a wrong checksum or URL | `fix:` | patch |
   | Docs, provenance wording, tooling | `docs:` / `chore:` | none |

   The shared next-version action reads the commit range; only `feat`, `fix`, `perf`
   and `revert` cut a release at all.

6. **Merge to `main` and let the automation run.** `release.yml` computes the
   version, tags, publishes the GitHub Release, then in parallel:
   - **mirror** — `tools/mirror_weights.py` downloads the pinned URL,
     verifies the digest, and attaches the `.pth` plus a `.sha256` file to the
     Release. Hugging Face stays canonical; this copy is for users whose
     network cannot reach the Hub. A failed mirror deliberately does not hold
     back the wheel.
   - **build + publish** — sdist and wheel to PyPI via Trusted Publisher, with
     a wheel smoke test in a clean interpreter.

7. **Write the release notes' provenance.** Every release carries the
   trainer's record — data recipe, fonts, crop counts, training config, git
   SHAs, known defects — and the CC BY-SA 3.0 attribution for the Armenian
   Wikisource material. That attribution travels in the release notes *and*
   the README's provenance section, and the word list's (CC BY-SA 4.0,
   including the Nayiri Armenian Lexicon's credit) in `NOTICE`; they are
   licence obligations, not courtesies.

8. **Then move Tetrak onto it.** Once the release is on PyPI, raise the floor
   of Tetrak's `[armenian]` extra in its `pyproject.toml` to the new version,
   in a pull request there. Tetrak's backend falls back to greedy decoding on
   an older library, so the floor is what guarantees the word list is used.

## What the code already guarantees

Worth knowing so you do not re-check it by hand, and do not weaken it:

- **A cached `.pth` is never trusted on its name.** `reader()` hashes the
  cached file against `WEIGHTS_SHA256` on *every* call and re-downloads on a
  mismatch. The filename does not change between releases, so this is the only
  thing stopping an upgrade from silently running the previous model. Anything
  that shortcuts it — trusting existence, caching the verdict — reintroduces
  exactly that bug.
- **No published checksum means no load at all**, rather than a warning.
- **Downloads are verified before anything is written**, and written
  atomically, so a failed download leaves no file for the next call to trust.
- **`weights_path=` goes to `<cache>/local/`**, never over the released
  weights' cache entry — a training run must not become what the next plain
  `reader()` call loads.

## Code-only releases

Leave `WEIGHTS_URL` untouched. The mirror job sees no change, prints
"Code-only release — no weights to mirror", and exits 0. That is not an error.

## Checks before merging

```bash
pytest                                             # both-or-neither, yaml/charset consistency
ruff check src tests tools && ruff format --check src tests tools
uv lock --check
python3 tools/mirror_weights.py --output-dir /tmp/mirror-check   # proves the pin resolves
```

That last one is the highest-value manual check: it downloads the exact URL
you pinned and refuses it unless the digest matches, which is the one mistake
the rest of CI cannot catch for you.
